# HTML报告设计与布局规范

本文件提供了创建专业、易读的HTML报告所应遵循的设计规范和最佳实践。在生成报告时，必须严格遵守以下指导原则。

---

## 1. 页面布局与尺寸 (Page Layout & Sizing)

为了确保报告在打印或导出为PDF时具有一致和专业的外观，所有内容都必须被设计为在标准的A4纸张上呈现。

### 1.1 A4页面规范

报告的样式表中如果没有设置背景颜色则需要包含针对打印媒体的 `@page` 规则，以定义页面尺寸和边距。

> **CSS 示例:**
> ```css
> @media print {
>   @page {
>     size: A4;
>     margin: 0.2cm; /* 统一页边距为0.2cm */
>   }
>   body {
>     -webkit-print-color-adjust: exact; /* 确保背景和颜色能被打印 */
>     color-adjust: exact;
>   }
> }
> ```

### 1.2 边距与留白 (Margins & Whitespace)

- **页边距**: 如果没有设置背景颜色，则需要设置足够的页边距，以确保内容不会紧贴页面边缘。建议统一设置为 **0.2cm**。
- **内容留白**: 避免页面内出现大面积的、不协调的空白。应通过合理的图文排版、调整段落间距和行高来优化布局，使页面显得饱满而又不拥挤。
- **章节间距**: 章节标题与上方内容之间应保持适当间距（建议 `margin-top: 20px`），但不应出现过大的空白区域。

### 1.3 组件完整性与分页控制 (Component Integrity & Page Break Control)

为了防止卡片、图表、章节标题栏或逻辑相关的内容块在打印/导出PDF时被分页符截断或遮挡其他内容，必须严格遵守以下规范：

**1. 禁止内部分页**: 对所有不可分割的组件使用 `break-inside: avoid;` 属性。

**2. 章节标题与内容绑定**: 章节标题（尤其是带有背景色或渐变的标题卡片）必须与其后续内容保持在同一页。使用 `break-after: avoid;` 防止标题后立即分页。

**3. 避免元素遮挡**: 所有元素必须使用标准文档流定位（`position: static` 或 `position: relative`），**严禁对章节标题或内容块使用 `position: fixed` 或 `position: absolute`**，以防止元素在分页时遮挡其他页面内容。

> **CSS 示例:**
> ```css
> /* 防止组件内部被分页截断 */
> .card, .chart-container, .info-block, .section {
>   break-inside: avoid;
> }
> 
> /* 章节标题卡片：防止内部截断，且标题后不立即分页 */
> .section-header, .chapter-title {
>   break-inside: avoid;
>   break-after: avoid;
>   position: relative; /* 使用相对定位，禁止使用 fixed 或 absolute */
> }
> 
> /* 如果章节标题在页面底部空间不足，则整体移至下一页 */
> .section-header, .chapter-title {
>   page-break-inside: avoid;
>   page-break-after: avoid;
> }
> ```

**4. 预留安全边距**: 在设计章节标题卡片时，应确保其 `margin-top` 足够（建议至少 `20px`），避免与上方内容过于紧贴。同时，标题卡片不应使用负边距（`negative margin`）。

## 2. 内容与排版 (Content & Typography)

清晰的结构和易读的文本是报告的核心。

### 2.1 字体选择 (Font Selection)

- **正文**: 优先使用无衬线字体（Sans-serif），因为它们在屏幕上具有更好的可读性。推荐字体栈：`'Helvetica', 'Arial', 'sans-serif'`。
- **标题**: 标题可以使用略带设计感的字体，但必须保证清晰易读。

### 2.2 文本颜色 (Text Color)

为了降低长时间阅读的视觉疲劳，正文文本应避免使用纯黑色 (`#000000`)。推荐使用深灰色，例如 `#333333` 或 `#212529`。

### 2.3 标题层级 (Heading Hierarchy)

必须使用 `<h1>` 到 `<h6>` 标签来构建逻辑清晰的标题层级。通过不同的字号、字重（`font-weight`）和颜色来区分不同级别的标题，使用户能够快速理解文档结构。

### 2.4 文本换行 (Text Wrapping)

对于短小的标题或关键数据，应避免发生不期望的换行。可以使用 `white-space: nowrap;` 来强制文本在同一行显示。

> **CSS 示例:**
> ```css
> .short-title, .key-figure {
>   white-space: nowrap;
> }
> ```

### 2.5 文本溢出处理 (Text Overflow)

当文本内容可能超出容器边界时，必须进行妥善处理，避免文本被截断而无法阅读。优先使用自适应高度（`height: auto`）而非固定高度，以确保所有文本内容都能完整显示。

> **CSS 示例:**
> ```css
> /* 推荐：允许容器自适应内容高度 */
> .auto-height {
>   height: auto;
>   min-height: fit-content;
> }
> ```

## 3. 数据可视化 (Data Visualization)

为正确的数据选择正确的图表类型至关重要。所有图表都应包含明确的标题、图例和坐标轴标签。

| 图表类型 | 适用场景 | 设计建议 |
| :--- | :--- | :--- |
| **折线图 (Line Chart)** | 展示数据随时间变化的趋势或连续变量之间的关系。 | - 坐标轴刻度清晰，单位明确。<br>- 线条不宜过多（建议少于5条），使用不同颜色或样式区分。<br>- 关键数据点可添加标记。 |
| **柱状图 (Bar Chart)** | 比较不同类别之间的数据大小，可以是垂直或水平的。 | - 类别标签清晰易读。<br>- 柱状图的宽度和间距应保持一致。<br>- 颜色应与报告整体配色方案协调。 |
| **饼图/环形图 (Pie/Doughnut Chart)** | 显示各部分占整体的比例。 | - 类别数量不宜过多（建议3-6个），否则会难以辨认。<br>- 必须标注每个部分的百分比。<br>- 环形图中间可用于显示总计或核心指标。 |
| **散点图 (Scatter Plot)** | 探究两个数值变量之间的相关性、分布和聚类。 | - 数据点不宜过多，以免过于密集。<br>- 可以添加趋势线来揭示变量间的关系。 |
| **表格 (Table)** | 精确展示结构化的、详细的数据。 | - 设计应简洁，避免过多的边框和装饰。<br>- 表头应清晰，使用加粗或不同背景色突出。<br>- 交替行使用不同底色（斑马条纹）可以提高可读性。 |

---

## 4. 总体设计原则

- **一致性**: 整个报告中的字体、颜色、间距和设计元素必须保持一致。
- **专业性**: **严禁使用任何Emoji图标**（如 📊、✅、⚠️ 等）。Emoji字符在PDF渲染时通常无法正常显示，会出现方框或乱码。如需使用图标装饰，应使用**SVG图标**或**图片文件**替代。

> **错误示例:**
> ```html
> <h2>📊 当前股价信息</h2>  <!-- 禁止：Emoji在PDF中无法显示 -->
> ```
>
> **正确示例:**
> ```html
> <h2>当前股价信息</h2>  <!-- 推荐：纯文本标题 -->
> 
> <!-- 或使用SVG图标 -->
> <h2><svg class="icon">...</svg> 当前股价信息</h2>
> ```
- **可访问性**: 确保颜色对比度足够高，以便色弱用户也能清晰阅读。文本大小不应过小。
- **响应式**: 虽然主要为A4设计，但HTML报告也应考虑在不同屏幕尺寸下的基本可读性，避免内容溢出。
